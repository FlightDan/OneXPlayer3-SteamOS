# OXP3 SteamOS 1.0.6 — Maintenance revision 1

内部版本 `1.0.6+maintenance.1`，对外项目版本保持 `1.0.6`。本次更新维护程序、在线下载入口、槽位切换及 Windows 安装器随附维护工具；其他组件以已经公开的 1.0.6 基线准备。

## 一键体检

概览新增“一键体检”。检查当前系统与槽位、系统枚举出的手柄、InputPlumber 和可选陀螺仪服务、OXP3 输入配置，以及受管文件和旧安装记录中的基线差异。结果按需检查、未能判断、提示、通过排列；展示差异路径与预期/实际摘要。

可变配置内容不同作为自定义提示，缺失文件及元数据差异单独列出。无法读取、记录损坏、检查限额和正在进行的维护操作不会显示为通过。首次事务在生成 index 前中断时仍能识别 pending；待完成事务存在时跳过基线比较，继续手柄和服务检查。检查不会创建维护状态目录，不运行修复、重启服务、修改配置或读取按键事件。

“导出诊断报告”在桌面用户的 `~/Downloads/OXP3/diagnostics/` 保存一个 ZIP，内含可读文本和 JSON。报告包含版本/型号、服务状态、输入设备名称和文件摘要；不包含配置原文、安装原件、密码、设备序列号、物理连接标识、按键事件或完整日志，也不会自动上传。

本次体检不证明实际按键已转发至 Steam 或游戏。反馈手柄问题时，仍需在 Steam 控制器测试中验证按键和摇杆，并附上使用模式、故障发生时间和导出的报告。

## GitHub 下载线路

设置新增“GitHub 下载线路”：默认自动、官方直连、`gh-proxy.com`、`ghfast.top`、`ghproxy.net`。自动模式先直连，再尝试备用线路；选择某条备用线路时优先尝试该线路。发布发现、签名目录、维护核心及组件下载使用同一策略。定时检查沿用保存设置；Bash 安装入口和 CLI 可用 `--github-network` 指定相同值。

线路只用于匿名访问本项目及 Opti2XMX 的公开 GitHub 发布资源。GitHub API 备用线路采用本次实测可用的 `gh-proxy.com`；Atom 直连。HTTPS、每跳地址限制、签名、哈希与大小核验仍然生效。连接失败、HTTP 错误或返回 HTML 会换线；传输中断、签名或哈希不符会报错并清理未完成下载，不拼接不同来源的数据。

2026-10-18 本机网络出口实测：三条备用线路的 1.0.6 签名目录及完整维护核心均与官方一致。核心 982,783 字节，SHA-256 `ffb01379ee50fbaf349e9dbb03e56b0fed2547ca24d0a04a9908dac06a4bef35`；使用正式公钥验证目录、核心 manifest 签名及全部 156 个文件哈希，通过。实际新网络策略也成功完成自动发布发现及三线路完整核心下载。

194 MB 运行库仅验证了小范围 Range；550 MB Windows 1.0.5 安装包仅验证了开始位置。`ghfast.top` 和 `ghproxy.net` 返回准确 206；`gh-proxy.com` 对这份 Windows 包忽略 Range，返回 200，不能保证断点能力。未通过这些线路完整下载大包，也没有中国大陆出口速度或稳定性验收。第三方服务可用性会变化。

运营方资料：[GH-Proxy](https://gh-proxy.com/docs/github-accelerator)、[ghproxy.net](https://ghproxy.net/)、[ghfast](https://ghfast.top/)。项目下载链接及选线示例见 [GitHub 下载线路](../../windows-installer/docs/GITHUB_DOWNLOAD_ROUTES.md)。

## KDE 语言和槽位切换

维护界面优先读取 Plasma 的翻译语言，随后读取 KDE 的 Language 设置，再回退到会话语言。KDE 已设置中文而区域格式或旧会话变量为英文时，维护器仍显示中文；不修改系统区域设置。

槽位切换移除开始时的勾选窗口，打开后直接显示当前槽、目标槽和“切换并重启”确认。确认后只读检查更新服务：后台更新检查正在运行时，再询问是否停止检查并重启；没有运行则直接进入受保护的切换操作。任何一个确认窗口取消都不会停止服务或重启。正在运行的 RAUC、排队任务或未知状态仍拒绝切换；不强行中断系统升级，不自动重试重启。槽位切换界面也优先跟随 KDE 语言。

维护器新增已有 `slot-switch` 组件的受管文件适配：更新固定的共享程序、授权规则和桌面入口，沿用快照、冲突检查及回滚。更新组件本身不会执行切槽、停止更新服务或重启；仅更新维护工具本体也不会暗中改动槽位组件。已有文件必须能通过维护记录或旧安装日志认证接管；自定义文件、依赖缺失、双槽兼容性无法确认时保留阻断。

沿用既有双槽迁移限制：若 A 槽已更新共享文件，B 槽首次接管时仍持有旧安装快照，维护器会拒绝过期快照与实际文件不符的操作。此版本不自动跳过或重写另一槽的旧记录，需要先复核两槽记录。

## 同步与验证边界

体检、下载和语言功能随维护核心更新，Windows 新装通过现有 `prepare-maintenance.py` 携带同一代码。槽位切换复用已有组件 ID 和新装部署入口。最终维护目录必须继续覆盖全部支持组件，引用附件保留。Opti2XMX 如产生新分片，仅许可证文本采用源码的 LF 换行，插件与运行库功能内容不变。

公开产物从既有公开 1.0.6 源码基线加本次白名单修改准备。CPU、原生功耗、controls 和所有研究代码不从当前开发工作区导入。

独立审查发现的记录结构损坏、显式自动线路优先级、首次事务中断漏报三项已修正并加入回归测试。源码回归、离线 Linux、最终签名产物和公开下载结果分别记录。实机升级和 Windows 公开发行仍须满足既有发行门槛；软件检查不能替代实机验收。
