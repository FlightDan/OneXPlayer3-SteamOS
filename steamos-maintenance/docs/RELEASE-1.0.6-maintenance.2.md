# 1.0.6+maintenance.2

此前体检把完整维护索引限制在 256 MiB。设备包含大量备份、当前和上一代快照时，索引可超过 1.5 GB，配置核对只能返回未知。

本修订按块解析旧格式记录，只保留活动槽当前代需要核对的元数据，并边读取边计算快照内容的摘要。其他槽、原始备份和上一代的内联内容不装入体检结果。读取仍校验完整 JSON、重复键、编码、文件一致性及未完成事务，不能把损坏记录解释为正常。

事务完整读取保留所有备份和代际信息，通过流式解析减少整份文本的临时副本，并在内存中复用重复的大快照字符串。持久化采用分块 JSON 编码，继续沿用私有临时文件、文件 fsync、原子替换、目录 fsync 的顺序。

## 备份兼容性

磁盘上的 `index.json` 和 `pending.json` 保持原 format 1 及完整 Base64 快照，旧版维护器能够继续恢复中断事务、还原原始文件与回滚。不会压缩或删除权威备份，也不会变更双槽共享记录的协议。

这次优化的是大记录处理时的内存与读写方式，原有 1.55 GB 备份文件不会自动缩小。原因是另一系统槽可能仍运行旧维护器，改变格式或外置快照会破坏它的恢复能力。磁盘去重迁移需要两槽的读写版本均具备兼容能力后另行实施。

文件差异只作为诊断结果，不能用于绕过不可变受管文件检查。测试设备已有 CPU 插件文件与维护基线不符，本修订不覆盖这些文件或重写其基线。

## 交付

项目显示版本保持 1.0.6，维护修订为 1.0.6+maintenance.2。新装载荷通过现有 prepare-maintenance.py 同步同一运行代码；组件 ID、选择、依赖和系统适用条件不变。完整签名组件目录及此前公开载荷继续沿用，暂缓公开的功耗研究代码不得进入本次产物。

源码回归、独立审查、掌机大记录只读测试、隔离状态下恢复/回滚，以及发布后的公开下载验证，分别记录在本次 Release 验收说明中。未完成的实机安装和重启不得记作通过。
