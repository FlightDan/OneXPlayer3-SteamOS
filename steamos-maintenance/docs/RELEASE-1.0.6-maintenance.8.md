# 1.0.6+maintenance.8 — HDR 呈现确认与安装器恢复镜像校验

2026-10-22。显示版本继续为 1.0.6。此修订继承 maintenance.7 的兼容更新，不覆盖 maintenance.7 已公开附件。

HDR 试用仅在 Vulkan present_id / present_wait 扩展和对应特性可用时运行。首帧必须取得有界的呈现完成回执，并且仍在试用期限内，才允许用户确认保存；缺少能力、超时或失败均拒绝确认，独立恢复任务继续负责切换后十秒回退。渲染完成信号量按交换链图像分配，避免跨图像复用时与呈现等待冲突。

移除维护器陀螺仪重启激活阶段遗漏的 BIOS 5.09 字符串拒绝，使预检和激活条件一致。精确内核、InputPlumber 版本、唯一 ACPI 接口、绑定恢复机制，以及固件上传前地址和芯片 ID 检查继续保留。机型独立性 7 项和绑定恢复 13 项回归通过，并经独立复审。

安装器在恢复镜像页提前检查 GPT 结构，误选单独 Btrfs rootfs.img 时显示中英文提示；压缩包解压后在虚拟机启动前检查。校验分区布局与主 GPT CRC，不宣称校验镜像内容或来源真实性。

发布脚本新增可选 KeyStore 参数，将既有签名身份路径交给原发布器，便于独立公开 checkout 原地复用正式身份；签名、公钥一致性、DPAPI 和 ACL 检查保持。正式公钥固定 LF 换行，避免 Windows Git 自动转换导致相同公钥被字节一致性检查拒绝。

源码文本默认使用 LF，Windows PowerShell/CMD/BAT 保留 CRLF。避免 Windows checkout 将 Linux 服务、配置和 YAML 转为 CRLF，导致部署生成器无法加入原有 ExecCondition 启动校验；第三方 Opti 原始文件仍按现有 -text 规则保留字节。

源码修复和独立审阅已完成，CI 输入按固定白名单重新生成并通过 16 项一致性检查、7 项输入回归。原生构建、最终签名载荷、实机升级与重启恢复验收及公开下载验证尚待完成；本文件不会把源码测试写为实机验收通过。未包含未公开动态功耗研究、设备记录、凭据或私钥。
