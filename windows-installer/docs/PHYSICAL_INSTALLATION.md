# 实际安装与系统准备

当前代码：2026-10-14，**OXP3 SteamOS 0.1.0 Beta**。操作流程见 [安装指南](INSTALLATION_GUIDE.md)，历史 ZIP 与当前代码差异见 [README](../README.md)。

## 目标与容量

普通启动进入真实安装流程。内置模式接受 NVMe / SATA；外部模式接受非系统 USB / SD / MMC。目标要求 GPT、512 字节逻辑扇区、在线可写及至少 64 GiB 连续未分配空间。不自动缩小 Windows、初始化 RAW、转换 MBR 或清空整盘。

默认容量为 64 GiB，当前代码支持 64G / 100G 快捷选项、自定义容量和使用全部所选空间。系统及启动约占 24.375 GiB，剩余用于 home；选择小于空闲区域的容量时，余下保持未分配。

准备阶段在任务自有镜像中扩展 home 的 GPT 范围与 ext4 文件系统，保留其余分区标识、名称、属性与内容。选入的已有准备镜像先复制，源文件保持不变。写盘计划必须与准备镜像系统范围的总容量完全一致，不能将 64 GiB 布局直接作为 100 GiB 安装写入。

历史 011613 / 013814 完整包没有该扩容更新，仍使用 64 GiB 实盘布局。

## 官方系统与组件

恢复镜像用于提供基础容器，3.8.14 下载标签不代表最终系统。默认单独准备固定目标 **SteamOS 3.10 / build 20260924.1000**，通过 RAUC / casync 索引和 desync 还原官方根系统，再核对实际 os-release 与精确内核。旧 3.8.14 根系统无法通过实盘来源检查。

“准备系统”中的恢复镜像与 3.10 镜像为两个子页。`.raucb` 更新包下载或本地选择后即可继续向导，进入安装后才联网重建根系统；已重建 `rootfs.img` 可直接导入。开始安装前接受已就绪更新包或根镜像，写盘前必须完成实际系统准备和版本检查。

所选设备修复、插件和 KDE 语言在准备镜像的 A/B 两槽配置并独立只读复核。可选修复或插件在组件写入前发现资源、版本或依赖不可用时，自动跳过并在完成页列出原因；依赖它的组件也跳过。组件写入中断、成功组件复核失败和基础系统故障仍停止安装。默认勾选不会绕过版本或依赖检查。新生成镜像直接配置；用户选入的已有镜像先复制。组件与设备边界见 [组件说明](COMPONENT_INTEGRATION.md)。

整合版信息从 `components/release.json` 生成，准备时写入 `/home/deck/OXP3-SteamOS-Version.md`；组件结果记录整合版和实际系统版本，详见 [版本说明](VERSIONING.md)。

## 工作空间

下载、解压、系统升级缓存、镜像准备和安装任务使用用户选择的本地工作空间，默认 `<工具目录>/work`。系统缓存为 `<工作空间>/steamos-3.10`，切换目录不会搬移旧缓存。

实盘工作空间初始至少预留 **45 GiB**，建议 **64 GiB**，普通恢复镜像与开发用已准备镜像使用同一最低门槛；演练另计 80 GiB 测试盘（最低 125 GiB，建议 144 GiB）。转换前根据源数据范围复查并保留 8 GiB 余量，支持稀疏文件时不按全部逻辑容量分配；不支持时按完整镜像容量检查。预算不是最终占用上限，额外下载与旧任务还会消耗空间。

总进度采用准备 32%、组件配置及复核 43%、rEFInd 3%、写入及读回 22% 的权重，显示两位小数及固定阶段编号。全部分区的写入和读回按字节累计，不随分区切换归零。阶段编号、日志与测量边界见 [进度及容量估算](INSTALLATION_PROGRESS.md)。

## 写入与保护

管理员助手重新读取设备身份、容量、总线、可用序列号与完整分区布局，冻结源镜像并核对范围。分区快照不完整或设备布局改变即停止。

追加 GPT 分区前执行原生卷发现预检。原生卷结构按 64 位对齐读取，检查全部范围并保留具体卷路径、索引、字节数和 Win32 错误；损坏或含糊记录不能按空卷处理。GPT 原条目的名称和属性保持原样。

2026-10-14 修复 G3E 在 78% / 04.00 出现的编号映射错误。Windows 的 `PartitionNumber`、原生记录数组位置和磁盘 GPT 槽位分别处理：已有编号 `1,2,3,15,16` 的五条记录保持原位，新记录从原生 `PartitionCount` 后追加，不能用 `Number-1` 索引。追加前核对全部原生记录与主/备 GPT，实际提交前再核对一次；追加后逐字节核对原 GPT 条目及新增条目的 GUID、范围、名称和属性。当前仅接受 128×128 字节、原生顺序与实际非空 GPT 槽位一致且连续的表；有空洞或顺序不一致时在写盘前拒绝，不自动重排。

新卷发现后，锁定遇到临时访问拒绝或共享冲突可限时重试 15 秒，每次复核设备、完整布局及卷范围。超时、身份改变或取消仍停止；清理时即使一个解锁失败，也关闭所有已持有的卷句柄。

仅在已确认的未分配区域追加八个 SteamOS 分区，对相关新卷绑定、锁定和卸载后写入，每个分区检查边界并读回核对。记录 `physical-state.json`、GPT 元数据备份与助手结果。实盘停止/中断保留现场，尚无自动回滚或续写。

“删除选定分区…”是安装前单独执行的操作，删除后重新读取快照。安装时保留的是该快照中仍存在的分区，无法恢复此前删除的数据。

## 引导与验收

内置安装要求当前 Windows 使用 UEFI 且 Secure Boot 关闭。向导在安装位置前提醒关闭安全启动，并要求启用 BitLocker / 设备加密的用户先保存恢复密钥、暂停保护；关闭安全启动或更改启动顺序可能触发恢复解锁。验证 Windows 正常启动后恢复保护。

创建 `SteamOS (OXP3)` 入口时按启动器页的“将启动管理器设为默认启动项”处理：内置实盘默认勾选，置于 BootOrder 首位；取消则追加到末尾，保留原默认顺序。两种模式均保留其他入口的相对顺序及 Windows Boot Manager，写前保存 `firmware-before.json`，读回核对后记录 `firmware-result.json`。失败时只在固件仍匹配本次写入的状态下恢复原顺序，不覆盖并发固件更改。选择随请求、任务、实盘计划和恢复记录保存；旧记录缺少该字段时按保留默认顺序处理。外部安装写设备自身的可移动 UEFI 启动文件，不改主机启动项。

固件 `HD()` 路径使用从实际 GPT 中按 GUID 和范围匹配的槽位编号。Windows 编号可能在重新挂载/重启后改变，不能直接写入固件路径。恢复流程仍严格核对原记录；若 Windows 重新编号，自动匹配会拒绝，需要单独复查，不能靠忽略编号差异直接续写。

rEFInd 默认关闭；开启后安装到新的 SteamOS ESP，不写 Windows ESP。其菜单默认系统独立于固件默认入口；是否重排 BootOrder 由上面的默认启动项选项决定。管理与恢复见 [rEFInd 说明](REFIND_OPTION.md)。

写入完成状态为 `awaiting-device-boot`。已有规划、独立 VHD 写入/读回、QEMU 扩容与虚拟 UEFI 登录证据，详见 [实现状态](../IMPLEMENTATION_STATUS.md)。真实 Windows 双启动、掌机固件、Steam 前端、新装按键/陀螺仪/HDR/覆盖层/CPU/Fan/Battery、重启/休眠与掉电仍需设备验证。Waydroid Android 镜像需要单独初始化和网络。
