# Windows 1.0.6：空间检查、安装日志与容量入口调整

2026-10-19。显示版本保持 1.0.6；使用新的源码提交与构建时间戳，不覆盖已公开附件。

本记录对应第一批空间、日志与界面修复。后续的 home 空闲块复制优化和系统/KDE 语言同步见 [2026-10-20 安装器记录](RELEASE_1.0.6_INSTALLER_HOME_LANGUAGE.md)；下文“完整写入空白区域”是本批修复当时的行为。

用户于 2026-10-19 确认测试完成并授权发布。代理执行的本地构建、自动检查及包完整性验证单独记录；本轮未新增代理执行的实机写盘或重启复验。

主安装及恢复流程现在自动把完整运行输出、阶段、任务目录和异常堆栈写入安装器旁的 `logs/installation-*.log`，实时刷新，支持运行时读取。管理员写盘助手在参数、任务或事件句柄验证前就建立独立 helper 日志，记录原先被顶层处理器丢弃的早期异常。子进程输出保留换行和空行。此前 `logs` 中主要是 Linux guest 的阶段输出，实际安装会话的 UI、助手错误和恢复记录则在工作目录中，导致用户提供的阶段日志不足以定位 Windows 写盘失败。原有会话与导出入口继续保留。日志不序列化安装请求或 deck 初始密码。

按用户要求隐藏“使用全部空间”按钮，并移除中英文引导中对此入口的提示；64G、100G 和自定义输入保留。仅隐藏快捷入口，不改变用户手动输入容量的既有校验。

Windows 上 QEMU 的 raw 镜像分配映射可能将稀疏空洞全部报告为数据。原复制预检因此把实际分配约 264 MiB 的测试镜像按 80 GiB 数据计算，再要求额外 8 GiB 空间，造成空间不足误报。现在对锁定的普通 raw 稀疏文件使用 Windows 原生已分配范围；按目标卷的分配单位向外取整并合并，兼容较大簇，避免低估目标开销。查询不可用时保留保守估算；qcow2 及其镜像图继续使用 QEMU 映射。保持非稀疏目标的完整容量检查。

这项修改修复复制预检的误判，不能据此把所有写盘故障归因于空间估算。隐藏快捷按钮后，自定义大容量仍沿用先扩容临时 home、再完整写入及读回目标分区的流程，包括空白区域。511.27 GiB 的安装容量意味着约 1 TiB 的目标盘读写。现有任务也保留 scratch、payload、镜像和恢复记录，重试有累积占用；本次不自动删除既有会话或更改恢复流程。
