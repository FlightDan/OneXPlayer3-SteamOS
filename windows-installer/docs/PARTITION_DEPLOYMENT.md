# Windows 分区部署

当前代码：2026-10-14。正常安装与工具自有 VHD 演练共用部分原生写入逻辑，但使用不同入口、目标权限与恢复规则。用户步骤见 [安装指南](INSTALLATION_GUIDE.md)。

## 正常实盘安装

`InstallationController` 在所选工作空间中完成镜像准备、组件配置、可选 rEFInd 与容量扩展。`PreparedDiskImage` 核对主/备 GPT、八个 SteamOS 角色、GUID、类型、名称、属性与范围，并在写入过程中持有源文件。

`PhysicalInstallation` 只接受用户确认的真实 GPT 未分配空间；按准备镜像生成八个新增分区，要求准备总容量与所选容量相等。已有分区条目、名称与属性保持。目标身份、布局与原生卷范围检查先于分区追加，新增卷绑定/锁定/卸载后逐分区写入并读回核对。

源文件不能来自多范围卷或与新增分区范围重叠的卷。身份或范围改变、源内容变更、不完整布局和无法可靠读取的卷记录均拒绝继续。

写入记录保存在本次任务的 `physical-state.json`、GPT 备份与助手结果中。实盘完成状态为 `awaiting-device-boot`，引导与硬件需要设备验证；中断不自动回滚、删除新增分区或续写。具体模式条件、容量与固件入口见 [实际安装](PHYSICAL_INSTALLATION.md)。

## VHD 演练与恢复

演练使用 `--rehearsal` 和工具自有的 VHD；`PartitionDeployment` 校验文件身份、所有权、虚拟磁盘 GUID、容量与布局。它不接受任意物理盘号作为演练目标。

有完整记录的任务可“继续上次演练 / 复查并继续”：逐字节复查已完成前缀，从头重写未完成分区，之后重新验证独立 UEFI 启动。旧日志、文件替换、源变化、损坏或记录缺失时拒绝自动恢复。详见 [恢复说明](INSTALLATION_RECOVERY.md)。

80 GiB 演练容器与实盘用户选择的安装容量是不同概念；演练预算另外计入测试盘，不能套用实盘工作空间预算。

## 验证边界

已有独立 VHD 分区追加、原文件保留、卷锁定、写入/读回、取消/恢复与虚拟 SteamOS UEFI 登录证据。当前容量扩展另在离线 QEMU 中验证 GPT / ext4 扩容与原源不变。索引见 [实现状态](../IMPLEMENTATION_STATUS.md)。

这些证据不代表实际分区删除、Windows 双启动、掌机固件、触屏、Steam 前端或真实掉电已经通过。早期 VHD 原型流水账已移入本地归档区。
