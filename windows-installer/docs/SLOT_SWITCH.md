# KDE 槽位切换 / 系统回退

安装器新增默认开启的 `slot-switch` 设备组件，在 KDE 桌面和应用菜单提供 **SteamOS 槽位切换 / 系统回退**。本次为源码集成；旧安装包和已经安装的系统不会自动获得新入口。掌机上的对话框显示、授权和真实重启仍需验收。

打开入口后显示当前槽、原定下次启动槽、当前系统版本，以及两槽的适配安装记录。安装记录明确标注为历史记录，官方更新覆盖槽位后不能用它证明实际系统版本或适配完整性。用户保存游戏和文件、点击“切换并重启”后，工具只选择另一槽并请求重启，不写入系统镜像，也不修改 EFI BootOrder。

切换后成功启动的槽会继续使用，直到下一次切换或系统更新。此操作不是完整数据恢复：两槽共享 home，游戏、存档和个人文件不会随系统槽回退。另一槽损坏、同样被覆盖，或者两槽都不能启动时，需要官方恢复介质；无法进入 KDE 时可使用官方开机恢复菜单。

## 更新适配版的后续方案

后续适配更新可以将完整的新系统及适配写入非当前槽，先验证兼容性和部署结果，再选择该槽试启动。启动成功确认前保留当前槽；更新失败可切回保留槽。更新器还需要镜像真实性检查、更新期间互斥、掉电恢复、启动成功确认和失败回退。本次没有实现适配版更新器，也没有解除 0.1.1 的系统更新保护。

## 实现与保护

- 独立 Python 程序、固定参数的入口脚本保存在共享 `/home/.oxp3-slot-switch`，目录由 root 拥有，普通用户不能修改；Python 使用 `-I -B`。
- 桌面快捷方式和应用菜单文件由 deck 拥有，随安装器所选语言命名。程序和两个入口通过现有共享 home 文件事务安装，原件只记录一次。每槽的 polkit 规则通过系统文件事务安装到持久 `/etc` 层；恢复组件时先检查整组文件是否被修改。
- 本地 active deck 会话只能通过固定脚本执行 `status` 或带已确认槽位和状态令牌的 `reboot`。如果官方更新没有保留 polkit 规则，pkexec 会要求普通管理员授权；共享入口仍保留，未设置可用管理员密码时需使用开机恢复菜单。
- 未知槽、缺失启动配置、`image-invalid` 标记、确认后配置变化、活动更新服务均拒绝切换。不停止正在运行的更新服务。切换时为原来未屏蔽的更新服务添加临时运行时屏蔽，复核其 inactive 状态，防止自动更新与槽位选择同时发生；原有屏蔽不撤销，失败时撤销自己的临时屏蔽，成功重启后由 `/run` 清空。其他自定义 root 更新程序也必须遵守这些服务保护。
- 使用官方 `steamos-bootconf config --no-create --image X` 更新目标的 `boot-requested-at`、`boot-attempts`，不清除 `image-invalid`。时间戳高于两槽现有请求值，避免时钟回退或原有未来时间戳让另一槽无法选中。读回 `selected-image` 必须等于目标才请求重启。
- 重启失败时，只恢复本次成功写入后仍未再次变化的目标配置。写入失败但文件发生变化时无法确认归属，保留配置并提示恢复菜单。此功能不保证任意断电时自动恢复启动配置，也不保证另一槽能成功启动。

## 验证入口

`--cli slot-switch-checks <只读 SteamOS 根分区 rootfs.img>` 在隔离 QEMU 中运行槽位控制、桌面对话逻辑、路径权限与共享 A/B 安装/恢复测试，并使用官方镜像中的真实 `steamos-bootconf` 操作一次性配置目录，验证 A→B、B→A 和未来时间戳。测试不会切换掌机槽位，也不会请求真实系统重启。

完整组件回归入口 `--cli integration-checks` 同样包含槽位切换测试。安装器源代码构建和这类虚拟验证不能替代实际掌机更新、重启和图形界面验收。
