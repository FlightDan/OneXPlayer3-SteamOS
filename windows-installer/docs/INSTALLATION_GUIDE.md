# ONEXPLAYER 3 SteamOS 安装与测试指南

适用范围：**2026-10-15 当前代码，OXP3 SteamOS 0.1.3 stable main-branch 候选**。GitHub 上传与发布状态尚未确认。本指南说明如何从 Windows 启动安装助手、设置工作空间、选择安装容量、准备系统、设置启动菜单，并检查安装结果。stable 是项目整合版的渠道标签。用户已完成有限的首次启动实机检查；SteamOS 精确版本、槽位、Steam 登录及完整 OOBE 未确认，自动跨版本适配尚未实现，详见[发布说明](RELEASE_0.1.3.md)。

本文描述当前源码行为，已有本地 ZIP 不会随源码和文档更新。115100 等历史包不代表包含最新的两个镜像子页或延后重建流程。本版已修复可复现的格式化拒绝并执行隔离验证；用户此前反馈已实机测试分区删除、剩余空间 NTFS 格式化和挂载分区到 SteamOS，但最新反馈称挂载仍不可用。新装镜像使用必需的私有本地空更新源，保持 `atomupd` 更新器运行并暂缓系统镜像更新；更新器正常时没有 SteamOS 更新候选。此策略只影响新准备的镜像，不修改已安装系统。若恢复更新或执行官方 SteamOS 系统更新，系统可能从 3.10 回滚至 3.8，并可能覆盖全部 OXP3 适配，包括 Wi-Fi 和手柄支持；该更新兼容性尚未验证。首次启动实机测试跳过系统下载后出现长时间黑屏，按住电源键关机再开机后桌面、Wi-Fi 和手柄正常；精确版本、槽位、Steam 登录及完整 OOBE 未确认。首次安装初始化黑屏处理步骤见下方“完成与首次启动”。旧暂停状态恢复方法见[首次启动与更新保护](FIRSTBOOT_INPUT_DECKY.md)。使用新包时确认 `build-info.json` 中的版本与构建编号；GitHub 上传与发布状态尚未确认，见 [README](../README.md)。

> **已知问题：首次安装初始化可能长时间黑屏。** 仅在初始化切换阶段出现此黑屏时，至少等待 **5 分钟**，再按住电源键关机并重新开机。Windows 镜像写入或真实系统更新显示进度时，不要强制关机。0.1.3 未修复此问题。

> **SteamOS 更新风险：**本构建当前暂停系统更新。若恢复更新或执行官方 SteamOS 系统更新，系统可能从 3.10 回滚至 3.8，并可能覆盖全部 OXP3 适配，包括 Wi-Fi 和手柄支持；该兼容性尚未验证。

> **SteamOS update risk:** OS updates are held in this build. Restoring updates or running an official SteamOS OS update may roll the system back from 3.10 to 3.8 and overwrite all OXP3 adaptations, including Wi-Fi and controller support. Compatibility has not been verified.

这是面向 ONEXPLAYER 3 的安装工具，包含设备专用适配。不要把这里的默认修复组合直接用于其他型号。当前运行包已经开放真实磁盘安装和分区删除；普通启动不是只读演示。外部 SD / SSD 的实机验证范围见实现状态。

## 1 安装前准备

先区分两种空间：**工作空间**是 Windows 中用于下载、解压和准备系统的本地文件夹，默认是工具目录下的 `work`，可以更换；**目标空间**用于最终安装 SteamOS，必须是选定磁盘上的连续未分配空间。二者的容量要求不能互相替代。

| 项目 | 本版本要求与说明 |
| --- | --- |
| 运行环境 | Windows x64；使用包内 .NET、QEMU 和配套工具，无需另装 WSL2、SDK、Node.js 或虚拟机软件 |
| 工作目录 | 完整解压到本地文件夹；配置页中可选择专用工作文件夹。实盘工作空间至少预留 45 GiB，建议 64 GiB；额外下载、源镜像和旧任务另占空间 |
| 目标空间 | 至少 64 GiB 连续未分配空间；当前代码支持 64 / 100 GiB、自定义容量和使用全部所选空间 |
| 目标磁盘 | GPT，512 字节逻辑扇区，在线且可写；不支持自动转换 MBR 或初始化 RAW 盘 |
| 内置模式 | NVMe / SATA，保留 Windows 和未被主动删除的已有分区 |
| 外部模式 | 非系统 USB / SD / MMC 设备上的未分配空间；装成可启动的完整系统 |
| 内置引导 | 当前 Windows 使用 UEFI，Secure Boot 关闭；首次启动仍需要设备侧验证 |
| 镜像与网络 | ZIP 不含 SteamOS / Android 系统镜像；准备 SteamOS 3.10 和部分后续初始化需要网络 |

开始前完成以下准备：

1. 把重要文件备份到另一块设备或可靠备份位置，并确认能打开。
2. 如 Windows 启用了 BitLocker / 设备加密，先备份并确认恢复密钥可用，再在 Windows 中暂停 BitLocker 保护。关闭安全启动或修改默认启动顺序可能使加密硬盘无法自动解锁，进入 Windows 时要求恢复密钥；没有密钥时可能无法访问加密数据。
3. 进入 BIOS / UEFI，提前关闭安全启动（Secure Boot），再返回 Windows 启动安装助手。当前 SteamOS / rEFInd 引导需要安全启动关闭。安装后验证 Windows 正常启动，再恢复 BitLocker 保护；暂停会减弱数据保护，不要长期暂停。
4. 准备可以启动的恢复介质，连接电源，关闭重要应用；安装期间保持设备连接和供电。
5. 确认安装助手、镜像和备份都不放在准备删除的数据分区里。
6. 记录目标磁盘型号、容量和当前分区。不要只凭“磁盘 0”或一个盘符判断设备，连接变化可能影响编号。

BitLocker 操作依据见 [微软 FAQ](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/faq) 与 [暂停保护说明](https://learn.microsoft.com/en-us/troubleshoot/windows-client/windows-security/suspend-bitlocker-protection-non-microsoft-updates)。安装助手不会代替你修改 BIOS、暂停保护或收集恢复密钥。

若只有一个装有 Windows 的 C: 分区，没有未分配空间，也没有可以放弃的数据分区，本工具不会自动缩小 C:。不要为了腾空间删除 Windows、EFI 或恢复分区；先完成备份和单独的空间规划，或使用满足条件的外部设备。

### 选择工作空间与估算占用

在前六个配置页中的“工作空间”卡片点击“选择文件夹…”。选择本地磁盘上的专用子文件夹，例如 `D:\OXP3-work`；不支持网络路径或直接使用盘符根目录。目录需要可写，建议使用支持稀疏文件的 NTFS 卷。设置保存在工具根目录 `workspace.json`，下次启动和管理员助手会使用同一位置。

| 流程 | 初始可用空间预算 |
| --- | --- |
| 实盘安装，普通恢复镜像 | 至少 45 GiB，建议 64 GiB |
| 实盘安装，开发选项中的已准备镜像 | 至少 45 GiB，建议 64 GiB |
| 虚拟盘演练，普通恢复镜像 | 至少 125 GiB（45 + 80），建议 144 GiB（64 + 80） |
| 虚拟盘演练，已准备镜像 | 至少 125 GiB（45 + 80），建议 144 GiB（64 + 80） |

这些是开始前预算，**不是最终占用上限或保证足够的固定值**。下载会消耗空间；每次转换镜像前还会按源数据范围复查并保留 8 GiB 余量。不支持稀疏文件时按完整镜像容量检查；扩大安装容量也可能增加准备阶段的占用。以当前阶段提示为准，不能只根据文件显示的逻辑大小判断实际磁盘占用。

2026-10-14 本地成功演练中，单次工作空间及配套工具实际占用约 **43.70 GiB**，据此设置最低 45 GiB、建议 64 GiB。目标系统的八个分区仍至少需要 **64 GiB 连续未分配空间**；45 GiB 是 Windows 工作空间要求。测量范围、阶段权重和问题定位编号见 [进度及容量估算](INSTALLATION_PROGRESS.md)。

切换工作空间不会搬移或删除旧下载、缓存或任务。要继续旧下载或查看旧演练记录，切回原目录；使用开发用 `prepared.img` 时，文件必须位于当前工作空间内，切换后需重新选择。下载、磁盘读取或安装进行中不能更换目录。不要把工作文件夹放到准备删除的分区，也不要删除尚需诊断的任务。

## 2 解压与启动

1. 将 ZIP **完整解压**，不要直接从压缩软件里运行 EXE。
2. 打开解压目录，确认能看到 `SteamOSInstaller.exe`、`app`、`runtime`、`guest`、`scripts`、`components` 等内容。
3. 双击根目录的 `SteamOSInstaller.exe`，根据 Windows 提示授予管理员权限。不要只复制一个 EXE 到其他目录运行。
4. 进入安装位置前，会显示“安装前：关闭安全启动，准备恢复密钥”对话框。按第 1 节完成准备后勾选确认，点击“进入安装位置”；尚未准备好则点击“退出，先做准备”。确认只是开放向导并读取磁盘，不会开始安装。安装位置页可点击“查看安装前准备提示”重新阅读。
5. 默认窗口最大化；左下角可以切换中文/英文和窗口大小。中间内容区可以向下滚动，主要导航按钮固定在底部。

左侧八个步骤可以用于查看和返回配置。能打开某页不代表已经满足安装条件；未完成的项目会标红，最终开始安装仍会检查前置条件。

“调试模式”默认关闭。开启后才显示高级工具、分区页“使用示例布局”和系统页“开发选项”。示例型号明确标为非实际设备，可以模拟删除，不能实际安装。关闭调试模式会清除示例选择和开发镜像模式，并保留已读取的真实磁盘列表。

调试模式用于显示开发入口，不会将普通安装改成演练。需要虚拟盘演练时使用专用 `--rehearsal` 启动入口。

## 3 安装位置

### 选择模式与磁盘

1. 选择“内置硬盘 · 双系统”或“外部 SD 卡 / SSD”。外部模式表示系统安装在外部设备上，不是制作恢复 U 盘。
2. 首次打开安装位置会自动读取本机磁盘，按钮旁显示“正在读取…”。读取结束后选择磁盘；需要更新时点击“读取 / 刷新本机磁盘”。返回此页不会自动清除已选位置。空盘或空读卡器不会使整个枚举失败；出现“分区布局不可用 / 分区读取不完整”时，该磁盘禁止安装和删除，先刷新或处理读取错误。读取失败时确认完整目录和管理员权限，再重试。
3. 从下拉列表选择磁盘，核对型号、容量和接口。
4. 查看分区表，寻找状态为“可安装 SteamOS”的“未分配空间”。

### 理解三种空间

| 表中看到的内容 | 含义 | 能否直接安装 |
| --- | --- | --- |
| D: 数据分区，容量 100 GiB，可用 60 GiB | 100 GiB 已经属于 D:；60 GiB 是它内部尚未使用的空间 | 不能直接当作未分配空间 |
| 未分配空间 100 GiB | 这段磁盘区域目前不属于任何分区 | 满足磁盘条件时可以选择 |
| 两段分开的 40 GiB 未分配空间 | 中间仍隔着已有分区 | 不能相加充当一段 80 GiB 安装空间 |

### 设置安装容量

选择符合条件的未分配空间后，默认安装容量为 **64 GiB**。可以点击 **64G**、**100G**、**使用全部空间**，或手动填写容量。按钮上的 G 沿用输入框的 GiB 单位（1 GiB = 1024³ 字节）；所选连续空间不足 100 GiB 时，100G 不可用。

“安装区位置”对新方案默认选择 **靠右**，也可选靠左。靠左时 SteamOS 从所选空间起点开始；靠右时 SteamOS 占用末端，剩余空间留在前面。两者均按 1 MiB 对齐，满足 4K 对齐。使用全部空间时两种布局相同。选择 64 GiB 并把余量建为 NTFS 时，预览分别为 `SteamOS 64 GiB | NTFS` 或 `NTFS | SteamOS 64 GiB`；这个选项只规划新的安装范围，不移动已有分区。旧保存方案继续沿用已保存的位置；旧方案缺少此字段时按原靠左位置解析。

界面会同时显示安装总容量、home 数据分区大小、剩余未分配空间和前后分区变化。安装容量包含约 **24.375 GiB 的系统及启动空间**，并不全部用于游戏。例如，64 GiB 安装的 home 约为 39.625 GiB，100 GiB 安装约为 75.625 GiB，均为格式化前大小。

选择更大容量时，准备阶段只扩展任务自有镜像的 home 分区和文件系统，保留其他系统分区标识与内容；用户选入的已有准备镜像会先复制。写入前要求准备布局与所选容量一致。使用全部空间只占用当前选中的连续未分配区域；手动选择较小容量时，余下空间仍未分配。

历史 011613 / 013814 包未包含后续扩容更新；请核对本次构建信息，不要混用旧包说明。

刷新或切换磁盘会清除原选择。返回修改容量、目标等配置后，也需要重新完成相关确认。

### 将剩余空间格式化为 NTFS

0.1.2 修复 Windows PowerShell 5.1 的多磁盘 JSON 枚举错误；隔离 VHD 的真实格式化、4K 对齐及共享文件读写已验证。用户此前反馈已于 **2026-10-15** 完成掌机实机分区删除、剩余空间 NTFS 格式化和挂载分区到 SteamOS 的测试；最新反馈称挂载仍不可用，所以此前挂载记录不构成当前版本实机可用证明，也不代表每种文件系统、重启自动挂载、休眠/加密卷、拔卡重连或完整安装至 OOBE 均已验收。

先选择未分配区域、SteamOS 容量及靠左／靠右位置，再点击“将剩余空间格式化为 NTFS…”。例如选择一段 400 GiB 空间并保留 100 GiB 安装，按钮只处理同一段区域中的 300 GiB 余量；靠左时余量在安装区之后，靠右时在安装区之前。使用全部空间时没有余量；创建 NTFS 至少需要 64 MiB。

核对管理员窗口中的磁盘、SteamOS 保留范围和 NTFS 范围，再确认操作。NTFS 使用 **1 MiB 分区对齐（满足 4K 对齐）和 4096 字节簇**。分区起点对齐与簇大小是两个设置；这里的 4K 对齐不表示支持 4Kn 磁盘，目标磁盘仍需 512 字节逻辑扇区。

**此按钮确认后立即创建并格式化 NTFS，不等待最终开始安装。** 完成后重新读取磁盘，并选中为 SteamOS 保留的空间；随后取消安装也不会自动删除已创建的 NTFS。若提示未确认完成，先看刷新后的布局，可能已有分区生成。

### 没有空间时删除不用的数据分区

“删除选定分区…”是单独的即时操作，**不等待最后点击开始安装**。删除的是整个分区，包含已经使用和未使用的空间；安装助手不能撤销这一操作。

用户反馈已于 **2026-10-15** 完成分区删除的掌机实机测试。该记录仅覆盖分区删除操作，不代表完整安装或首次开箱配置（OOBE）已验收。

1. 先检查盘符内的文件，确认确实可以全部放弃或已备份。
2. 在列表中选中允许删除的数据分区；Linux／未识别文件系统分区同样需要满足保护检查。Windows 无法检查其内部文件，删除前自行确认整个分区都可清空。
3. 点击下方“删除选定分区…”。如果按钮不在当前视野，向下滚动。
4. 在管理员确认窗口再次核对磁盘型号、磁盘号、分区号、盘符、卷名和容量。
5. 不确定就选“取消”。确认无误后，勾选“我已备份需要的文件，确认清空上面选定的分区”，再点“立即删除此分区”。
6. 等待刷新。若释放出的连续空间满足要求，程序会自动选中它；相邻未分配空间会按新的磁盘布局显示为合并区域。
7. 在释放后的空间内设置安装容量，再继续向导。若仍不足 64 GiB，先检查布局，不要连续盲目删除其他分区。

例如，删除 96 GiB 的 D: 分区会释放整个 96 GiB，而不是只释放表里显示的 40 GiB“可用”空间。D: 中已有的文件同样会丢失。

系统、启动、EFI、MSR、恢复和 BIOS 引导分区受到保护；实际只读、脱机、受保护或元数据不足的分区也不能删除。安装助手、工作空间、Windows、临时文件、页面文件或转储文件所在卷受到保护。

普通 Windows 数据卷需能安全访问，支持 NTFS、FAT32、exFAT 和 ReFS。Linux／未识别文件系统分区可以在原生 GPT 身份、范围和保护属性检查通过后删除。Windows 对非 Windows 分区显示“隐藏”不等同于实际 GPT 保护属性；工具会额外核对实际属性，不会为了放行而清除保护。能删除只表示允许清空所选分区，不表示程序已经识别其中的系统或数据。

若按钮不可用，不要转用强制删除命令绕过保护。若提示布局发生变化，重新读取并核对目标。若删除后刷新失败，先重新读取磁盘；不要把“没有看到成功提示”理解为一定没有删除。

### 第一次安装确认

选好空间并点击“下一步”后，会出现数据安全确认，列出目标范围。点击“已备份，继续”只是进入系统准备页；真正安装要等到后面的方案确认和开始安装。之前单独执行的分区删除不会因此延后或撤销。

## 4 准备系统

点击左侧“准备系统”会展开两个子项，按“恢复镜像 → 3.10 镜像”依次准备。两个页面均提供下载地址、复制地址及本地文件选择；下载或导入完成后自动显示本地路径。返回子页保留选择。

### 恢复镜像

**向导下载：**默认使用官方 ZIP，也可选官方 BZ2 或自定义 HTTPS 直链。阅读并接受 SteamOS 下载条款，点击“下载 / 继续”。可以暂停，之后在同一工作空间继续同一来源的下载记录。“重新下载”新建记录并保留旧记录；更换来源使用独立目录。自定义来源需要指向镜像文件的 HTTPS 直链，不能填网页地址。

**本地镜像：**点击“选择文件…”，支持 `.img`、`.img.bz2` 和 `.img.zip`。压缩的镜像由准备过程处理，不需要手动改扩展名。

BZ2 解压可能耗时较长，安装进度会提示；选择 ZIP 或原始 IMG 不显示该 BZ2 提示。“复制地址 · 手动下载”只复制地址；外部下载完成后，在下方选择本地恢复镜像。主向导无需开启调试模式。

预置下载名称中的 **3.8.14 是恢复镜像版本**，ZIP 标为“推荐”。恢复镜像提供基础容器，最终默认系统是 **SteamOS 3.10 / build 20260924.1000**。程序在工作空间整合 3.10 后再部署，不会先向目标磁盘安装 3.8.14 再升级。

### 3.10 镜像

1. 在线下载时，阅读并接受下载条款，点击“下载 / 继续”。官方地址提供 `.raucb` 更新包；此页只下载更新包并读取包内信息，不重建 5 GiB 的系统镜像。
2. 手动下载后，在下方“选择本地 3.10 镜像”中选择 `.raucb` 文件。也可选择已重建的 5 GiB `rootfs.img`，不接受把完整恢复镜像当作根系统分区镜像。
3. 文件就绪后，路径会自动填入下方输入框；已有文件在重新打开时自动显示。点击“下一步”进入选择安装内容，无需等待重建。
4. 点击最后的“开始安装”后，程序才为 `.raucb` 联网获取系统数据块、重建 `rootfs.img`，核对实际版本和内核，再整合恢复镜像。只有 `.raucb` 不代表已有完整的 5 GiB 系统数据，安装时仍需联网；已有数据可复用。

本地选择 `.raucb` 不要求勾选在线下载条款；导入成功或失败会在本地文件选择附近显示，成功后可进入下一步。安装阶段 `01.02.01` 显示“正在读取本地更新包”，`01.02.03` 显示“重建系统镜像”；重建百分比和 5 GiB 容量表示已重建数据，不是下载量。使用已重建的 `rootfs.img` 时无需重复重建。

3.10 的“重新下载”重新获取更新包，恢复镜像的“重新下载”则建立新的下载记录。切换工作空间不会搬移任一页面的文件。

调试模式下，“开发选项”中的 80 GiB 已准备镜像用于开发复用；普通首次安装保持关闭。80 GiB 指准备镜像容器，不是最终安装容量。不要把其他来源的镜像改名为 `prepared.img` 来跳过准备。

下载完成后确认本地镜像路径已经显示，再进入下一步。网络下载和后续系统准备是不同阶段；下载完成不等于已经准备好全部安装内容。

## 5 选择安装内容

上一页“3.10 镜像”默认使用 SteamOS 3.10；本页选择设备修复、插件和 KDE 语言。本版本实盘来源检查不接受旧 3.8.14 根系统；“系统版本选项”中取消升级可能导致后续检查拒绝安装，而不是自动获得兼容的旧版安装路径。

设备修复/适配默认全选、默认折叠，展开可逐项调整，包括按键、陀螺仪、HDR、覆盖层及设备控制相关内容。组件会检查版本和依赖；不要把被拒绝或跳过的项目当作已经安装成功。

可选修复和插件资源未备齐、版本不兼容或依赖不可用时，安装器会自动跳过并继续系统安装；完成页列出“已跳过 / 不可用”的项目、系统槽位和原因。网络问题导致插件资源缺失也适用此规则。磁盘满、I/O 错误、组件写入中断或引导失败仍会停止安装。预装使用离线资源，插件首次启动后的联网能力另行验证。

当前默认修复包含 Steam 首次启动父目录权限、GM7 休眠参数、xe DSB 关闭配置、BE201 Wi-Fi／蓝牙固件和音量服务通知配置。GM7 参数只按已选择目标 SSD 匹配；其他磁盘不添加。DSB 当前保持 `enable_dsb=0`，重新开启留待后续实机对比，不作为本次安装步骤。固件补齐不代表 Wi-Fi 历史复发已根治。

第三方插件预装包括 Decky Loader 及游戏库、封面、设置等插件，依赖关系按界面处理。首次安装、首次登录、在线资源加载和插件实际可用是不同环节，需分别测试。

其他设置中的“SteamOS 桌面模式 应用商店 · 中科大 Flathub 源（可选）”在中文界面默认开启、英文默认关闭；手动选择后不会随切换界面语言改变。“SteamOS 桌面语言（KDE）”默认跟随安装器语言：中文对应简体中文，英文对应 English；手动选择其他语言或“保持系统默认”后，切换安装器语言不会覆盖该选择。桌面语言在安装后登录 KDE 时生效，Steam 游戏模式的语言需在 Steam 设置中单独选择。

旧运行包的桌面语言默认“保持系统默认”，仅将安装器切换为中文不会改变安装后的英文桌面。已安装的系统无需重装：在桌面模式的 System Settings → Region & Language 中把简体中文设为首选语言，应用后注销并重新登录。当前源码与新构建修复了新安装的默认值，已有 ZIP 和已安装系统不会自动更新。

Waydroid 选项是 Android 宿主适配；ZIP 不含 Android 系统镜像，后续初始化需要单独入口和网络，不代表勾选后即可离线使用 Android。

## 6 共享分区挂载功能（暂时隐藏）

挂载功能目前暂时隐藏，新安装不显示也不提供挂载选择；选择安装内容后直接进入“确认方案”。本节保留底层实现信息供维护参考，不是当前安装操作流程，也不代表当前实机可用。用户此前于 **2026-10-15** 反馈过掌机实机挂载测试，但最新反馈称挂载功能仍不可用；此前记录只是历史事实，未覆盖所有文件系统、重启后自动挂载、休眠/加密卷、拔卡重连或日常长期使用。

### 底层实现记录

支持符合条件的 GPT NTFS、exFAT、FAT32、ext4 和单设备 Btrfs 数据分区；ext4/Btrfs 通过文件系统签名识别，可用于 GPT SD 卡，并保留卡内文件权限。MBR 分区不支持。系统、启动、恢复和受保护分区不在候选列表中。

底层界面实现中，每个选项显示磁盘、分区、容量及 `/mnt/shared/share-d...-p...` 路径。安装前重新核对分区 GUID、设备身份和范围；分区已变化时刷新并重新选择。旧确认方案实现可包含所选分区和挂载路径。

安装后通过持久 `/etc/fstab` 在访问时挂载；可在文件管理器打开对应路径。缺盘不阻止正常启动。未修改配置的挂载预检查失败会记录告警并继续系统安装；安装结果中可查看该告警。已有挂载事务、配置写入中断或底层存储错误仍会停止。权限设置用于共用文件，**不会自动建立或添加 Steam 游戏库**。Windows 未完全关闭、处于休眠或加密的卷可能无法访问；工具不会强制清理休眠文件。0.1.3 新装镜像使用私有本地空更新源，保持 `atomupd` 更新器运行并暂缓系统镜像更新；正常时没有 SteamOS 更新候选。此设置只影响新准备的镜像，不改已安装系统；恢复更新或执行官方更新可能使 SteamOS 从 3.10 回滚至 3.8，并可能覆盖全部 OXP3 适配，包括 Wi-Fi 与手柄支持。旧准备镜像须从官方原始下载重新准备。

完整全新安装至 OOBE 仍待验收。

## 7 确认方案

核对目标磁盘、未分配范围、所选安装容量、home 数据空间、镜像路径、系统版本及已选组件。展开分区变化明细，理解哪些分区保留、哪些分区新增。64 GiB 是 SteamOS 总安装容量，其中系统及启动约 24.375 GiB、home 约 39.625 GiB（格式化前），不包含另建的 NTFS 余量。

这里的“保留已有分区”指当前快照中仍存在的分区。如果此前执行过“删除选定分区”，被删除的数据不会出现在保留范围，也不会在安装时恢复。

确认备份和范围后，在加粗的确认卡片中勾选“我已备份重要数据，核对目标范围并确认格式化安装”，再继续到启动器安装页。未勾选就点下一步时，会滚动并聚焦到确认项，按系统动画设置提示边框；勾选后提示清除。若返回修改目标或其他配置，按提示重新确认。

## 8 启动器安装

rEFInd 默认不勾选。不开启时仍使用正常的 SteamOS 引导路径；开启后增加双系统启动菜单。

需要菜单时，勾选“安装 rEFInd 双系统启动菜单”，选择默认 SteamOS 或 Windows，再选择“一直等待选择”或倒计时。倒计时可设 1–3600 秒，初始值为 5 秒。若无法唯一识别 Windows EFI 分区，默认 Windows 选项可能被拒绝，先核对磁盘信息。

rEFInd 安装到新建的 SteamOS EFI 分区，保留原启动文件的备份。**菜单默认系统与 BIOS / UEFI 默认启动项是两个设置**。

本页顶部“将启动管理器设为默认启动项（推荐）”在内置实盘安装中默认勾选。勾选后，安装完成时将 `SteamOS (OXP3)` 排到固件 BootOrder 首位；启用 rEFInd 时重启先进入其菜单，否则直接启动 SteamOS。保留 Windows Boot Manager 和其他原入口的相对顺序，写入前备份原 BootOrder，并读回核对。取消勾选会保留原顺序，重启可能仍进入 Windows，需要手动从 UEFI 菜单选择 SteamOS。

外部安装和虚拟盘演练禁用此默认启动项选项，主机启动顺序保持不变。更改启动顺序也可能触发 BitLocker 恢复，必须提前保存恢复密钥并暂停保护；验证 Windows 正常启动后恢复保护。仅勾选默认启动项不会自动安装 rEFInd。

仅选择“配置 rEFInd · 预览与导出”会生成配置片段，**不等于安装启动菜单**。不要把导出的片段直接当作完整的目标配置覆盖已有引导文件。

掌机触控是否能在 rEFInd 中使用取决于固件接口；当前虚拟机证据不代表 OXP3 触屏已实测。无法触摸时使用固件支持的实体输入或键盘。当前用户向导没有承诺一键卸载已安装的 rEFInd；涉及恢复时保留任务记录和备份，按具体目标处理。

在此页点击“开始安装”才会启动安装准备和写入流程。

## 9 安装进度与停止

准备阶段会解压镜像、获取目标系统、部署所选组件，并按所选容量扩展数据空间。实际写入前再次核对设备身份、完整分区布局、准备镜像容量和原生卷范围；检查通过后才追加 SteamOS 分区、写入内容并读回核对。未获得可靠总量的步骤可能显示等待动画，不代表已经卡死。

左侧已完成配置显示绿色；未完成且已尝试离开的步骤显示红色，返回对应页面处理提示。详细日志默认折叠，点击后展开并随窗口高度扩展；界面只显示最近一部分内容，需要完整记录时使用“导出详细日志…”。

出现错误时先展开详细日志，查看当前阶段和最后一条错误。组件或来源检查失败可能发生在实际磁盘写入之前；若已经进入写盘阶段，停止后可能保留新增分区或部分已写内容。

需要停止时使用右上角红色“停止安装”按钮，等待当前操作结束，窗口保留以便导出日志。关闭窗口也会先请求停止，等待后端结束、释放资源并保存日志后自动关闭；不要拔盘、结束正在写盘的助手进程或直接断电。停止不是回滚，已经完成的删除和写入不会自动恢复。

## 10 完成与首次启动

**已知问题：首次安装初始化切换阶段可能长时间黑屏。** 用户实测首次启动跳过系统下载后黑屏，按住电源键关机并重新开机后进入桌面，Wi-Fi 和手柄正常；精确 SteamOS 版本、活动槽位、Steam 登录与完整 OOBE 尚未确认。如果首次安装中遇到相同的初始化黑屏，等待至少 **5 分钟**，再按住电源键关机并重新开机。仅对初始化黑屏执行；Windows 镜像写入或真实系统更新正在显示进度时不要强制断电。此已知问题尚未修复。

实盘安装成功后，Windows 当前用户桌面会自动生成 **重启到 SteamOS.bat**；中断恢复成功后也会生成。不需要勾选插件或安装 rEFInd，保留该 BAT 即可在关闭、移动或删除安装器后继续使用。

双击脚本，允许管理员权限并确认已保存工作后才执行重启。内置安装使用本次登记的 `SteamOS (OXP3)` 启动项设置一次性 BootNext，读回一致后重启，不修改默认 BootOrder；启用 rEFInd 时会先进入其菜单。外部安装不登记主机启动项，脚本重启进入 UEFI 设置，需要手动选择外部安装盘。

脚本检测到启动项被删除或改变时会显示错误；重启请求失败时尝试恢复原 BootNext，并保留其他程序后续改写的值。取消管理员提示或重启确认不会请求重启。桌面目录不可写等原因导致生成失败时，完成页和日志会提示原因，已完成的系统安装保持成功；已有同名文件会保留，必要时生成带编号的新文件。

实盘流程显示“写入已完成，等待掌机启动验证”时，表示安装器完成了自己的写入检查，还需要在设备上启动验证。不要把它理解成 Windows 双启动、Steam 前端和全部驱动均已通过。

1. 保存任务记录和错误信息，等待程序结束当前操作。
2. 保持外部安装盘连接；通过设备的正常重启和固件启动菜单进入目标系统。具体按键以设备固件界面为准。
3. 内置安装勾选“将启动管理器设为默认启动项”后直接重启进入 SteamOS / rEFInd；未勾选时从 UEFI 启动菜单选择 `SteamOS (OXP3)`，原默认顺序保留。完成页按本次选择给出提示；设置了默认项时“重启到 SteamOS”执行普通重启，未设置或外部安装则进入固件设置供手动选择。
4. 外部安装选择对应设备的 UEFI 入口；外部安装不修改当前主机的启动顺序。
5. 如启用了 rEFInd，确认菜单、默认系统和倒计时符合设置，再进入 SteamOS。
6. 返回 Windows 验证原系统能正常启动，检查原有文件和分区仍可用。如要求 BitLocker 恢复密钥，使用安装前保存的密钥解锁。验证成功后恢复 BitLocker 保护，不要长期暂停。

完成页的重启命令直接继承安装器的管理员权限。每次尝试在本次 `install-session-*` 目录保存 `restart-*.jsonl`：先写入调用记录，再记录可获得的进程 ID、退出码和标准输出／错误；失败时界面显示错误码及日志位置。成功立即重启时，进程退出后的记录可能来不及保存。这些日志也包含在“导出日志”中。

### 首次启动停留 Logo 时

厂商 Logo 不能单独证明系统死机，也不能单独证明某项修复失效。此前 G3E 实机已完成写入读回，但首次启动仍未通过；115100 修复包尚未在这台设备上部署和验收。

可连接键盘尝试 `Ctrl+Alt+F4`（部分键盘需要 Fn）；当前引导配置使用 `fbcon=vc:4-6`，F3 无反应不足以判定系统未启动。如果能登录或建立已有可信的 SSH 连接，先保存当前槽、`uname -r`、`/proc/cmdline`、Steam／显示服务状态及本次启动日志。

SSH 提示 `Connection refused` 表示该地址的端口未接受连接，可能尚未开启服务；它不等于密码错误。路由器登记了 `steamdeck` 或能够 ping 通，也不代表 Steam 界面正常。记录等待时间和网络变化，保留安装任务，不根据 Logo 截图直接认定权限、DSB 或硬件损坏是唯一根因。

| --- | --- |
| 找不到运行库、guest 或脚本 | 重新完整解压；不要单独移动 EXE。检查解压是否完成或有文件被隔离 |
| 读取磁盘失败或拒绝访问 | 用根目录正常启动程序并处理管理员提示；保留具体错误后重试，不需要全局修改 PowerShell 执行策略 |
| 有很多“可用”空间但无法安装 | “可用”可能属于现有卷内部；需要一段至少 64 GiB 的未分配空间 |
| 删除按钮是灰色 | 当前行不是允许删除的数据分区，或触发系统/工作目录/卷状态保护；示例和演练也有各自限制 |
| 删除结果不确定或刷新失败 | 重新读取磁盘，按当前布局判断；不要立即再次删除或安装 |
| NTFS 创建/格式化失败 | 已创建的分区可能仍保留。先刷新并核对磁盘、范围、文件系统，保留 `format-result.json` 和错误；不重复格式化既有分区，不根据失败提示认定没有写入 |
| 无法选择共享分区挂载 | 挂载功能目前暂时隐藏，新安装不提供挂载选择；选择安装内容后直接进入“确认方案”。此前实机反馈是历史记录，最新反馈称挂载仍不可用 |
| 下一步提示容量问题 | 当前代码检查容量不小于 64 GiB 且不超过所选连续空间；查看页面提示并重新确认。旧 011613 / 013814 包实盘仍固定 64 GiB |
| 镜像下载没有开始 | 检查条款确认、网络和 HTTPS 直链；本地已有镜像可以直接选择 |

| 本地选择 .raucb 后没有重建 | 这是预期行为；文件就绪后可点下一步，开始安装后才获取系统数据并重建 |

| 工作空间不足 | 查看工作空间卡片的可用空间与阶段预算；停止当前任务后更换本地文件夹。初始预算不是占用上限，不要误删待诊断任务 |
| 找不到容量、剩余 NTFS 或日志导出入口 | 核对实际构建与包内界面；不要仅依据最新指南判断历史 ZIP 已包含后续功能 |
| 找不到高级工具或示例布局 | 开启默认关闭的“调试模式”；开启调试不等于进入演练 |

| 提示设备或布局改变 | 停止使用旧选择，刷新磁盘并重新核对，不要绕过检查 |
| 写入后中断 | 保存所选工作空间中的任务目录、physical-state.json 和日志；不要直接删新增分区或再次覆盖安装 |
| 找不到 SteamOS 启动项 | 先确认安装结果与模式，再查看正确设备的 UEFI 启动菜单；保留现有 Windows Boot Manager |
| 重启仍进入 Windows，看不到 rEFInd | 内置安装需勾选“将启动管理器设为默认启动项”；菜单中的默认 SteamOS 不会改变固件顺序。未勾选、外部盘安装或使用旧包时，从 UEFI 菜单手动选择 SteamOS / 安装盘 |
| 关闭安全启动后 Windows 要求 BitLocker 密钥 | 使用事先保存的恢复密钥；没有密钥时可能无法解锁加密数据。更改前先备份密钥并暂停保护，验证 Windows 正常启动后恢复保护 |
| rEFInd 无法触摸 | 固件触屏支持仍待验收，尝试可用的实体输入；记录固件版本、方向和具体画面 |
| 无法默认启动 Windows | 检查 Windows EFI 分区是否唯一识别；配置导出或 EFI 探针测试不等于真实 Windows 引导成功 |
| 插件装好却不能联网或显示 | 区分首次登录加载、联网初始化和插件本身错误，记录具体插件与错误，不要按全部组件失败处理 |

“继续上次演练 / 复查并继续”是虚拟盘恢复入口，不代表可以自动续写任意实盘中断任务。实盘恢复以本次状态记录和具体错误为依据。

## 13 保留日志与反馈

优先在安装进度或结果页点击“导出详细日志…”，保存诊断 ZIP；运行中也可导出当时快照。导出包含界面快照、任务的 `.log` / `.json` / `.jsonl` / `.txt` 记录、续写日志和部署诊断，不含系统镜像或二进制。`export-info.json` 记录版本、系统、已收集和跳过的文件；无法导出某项时查看其中说明。

完整界面日志自动保存在 `<工作空间>/install-session-<任务ID>/ui.log`，演练续写日志为 `ui-resume-*.log`。通过“查看任务记录”或结果页“打开任务文件夹”查看。写盘阶段还可能包含 `physical-state.json`、GPT 元数据备份和助手结果；这些恢复现场文件仍应保留在原任务目录。工具根目录 `logs` 下的额外开发诊断可按实际错误补充，不要只保存最终截图。

反馈时提供以下信息即可开始定位：

- 整合版号、完整测试包文件名或构建编号、设备型号、Windows 版本、内置/外部安装模式。
- 目标磁盘容量、GPT 与逻辑扇区信息、删除或安装前后的布局。
- 工作空间路径与可用空间、所选安装容量、镜像来源、目标系统版本、调整过的组件、是否安装 rEFInd。
- 从哪个页面、点哪个按钮开始出现问题，错误全文与最后一段日志。
- 是否已经确认删除、是否已经进入写盘、是否重启或拔插过设备。

分享日志前检查是否含个人路径、用户名或其他私密信息。不要发送 BitLocker 恢复密钥、密码或令牌。
