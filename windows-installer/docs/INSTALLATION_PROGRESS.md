# 安装容量、总进度与问题定位

适用：2026-10-14 当前源码构建。更新源码不改变已发布的旧 ZIP。

## 工作空间

Windows 工作空间至少预留 **45 GiB 可用空间，建议 64 GiB**。普通恢复镜像与开发用已准备镜像采用同一最低门槛。虚拟盘演练另计 80 GiB 测试盘，即最低 125 GiB、建议 144 GiB。最终 SteamOS 目标仍至少需要 **64 GiB 连续未分配空间**。

2026-10-14 最新成功 VHD 演练，单次工作空间与配套工具实际占用约 43.70 GiB；64 GiB 目标的文件系统使用约 8.50 GiB，home 实际可用约 38.88 GiB。稀疏文件的逻辑容量不等于实际占用。45 GiB 是测量得出的最低预留值，并非任意选项、文件系统和下载组合的容量保证；旧任务、额外源文件、更大安装容量和不支持稀疏文件的工作卷可能需要更多空间。转换前继续按数据范围复查并保留 8 GiB 余量。

保留的原始测量目录：`E:\steamosworkspace\capacity-mock-20261014-032559\evidence`，包含 `REPORT.zh-CN.txt`、`progress-bar-calibration.json`、`capacity-and-progress-estimates.json`。该成功样本关闭了因缺少既有 remote 而拒绝安装的 `flathub-ustc`，已缓存官方根系统；没有测量首次 3.10 根系统网络下载和掌机首次启动。中文默认配置的失败日志也完整保留。这些边界不能用于宣称所有默认组件已通过。

## 总进度

“准备系统 → 3.10 镜像”页只下载或导入 `.raucb` 更新包、读取索引并显示本地路径；文件就绪即可进入下一步，不在此页重建系统镜像。在线下载显示更新包的实际字节、总量与速度，本地导入不要求勾选下载条款，导入结果或错误显示在本地文件选择附近。数据保存在当前工作空间的 `steamos-3.10/`，切换空间会重新检查该空间的文件。

点击“开始安装”后才重建 `.raucb` 对应的系统镜像，并检查、复用已有系统数据；缺少的数据仍需联网获取。阶段细分为 `01.02.01` 读取本地更新包（在线入口为下载更新包）、`01.02.02` 提取索引、`01.02.03` 重建系统镜像、`01.02.04` 使用本地缓存并转换恢复镜像、`01.02.05` 在虚拟机中整合系统。`01.02.03` 的百分比及 5 GiB 容量表示已重建数据，不是网络下载量；界面统一显示“重建系统镜像”。选入已重建的 `rootfs.img` 时直接使用工作副本。转换和整合仅在已确认的节点推进总进度。

| 工作 | 权重 | 正常进度区间 |
| --- | --- | --- |
| 准备系统 | 32% | 0–32% |
| 组件配置及独立复核 | 43% | 32–75% |
| rEFInd | 3% | 75–78% |
| 全部分区写入及读回 | 22% | 78–100% |

总进度表示已完成工作，不是剩余时间。解压、系统还原、虚拟机准备和导出没有可靠的总字节时，按成功完成的节点推进；长操作期间百分比可能保持不变，应同时查看当前操作和详细日志。组件按 A/B 槽已返回的组件记录累计，物理安装的组件阶段内部约 88% 用于配置、12% 用于独立复核。只有后端成功返回才确认整个阶段完成。

全部分区的写入和读回按 `Σ(已写字节 + 已核对字节) / (2 × Σ分区大小)` 累计，各分区按实际大小占比。只恢复虚拟盘时，已完成分区经过重新核对后才计入进度。跳过准备、组件或 rEFInd 时直接计入该阶段的份额，后续编号和权重保持固定；已准备的阶段不重复计时。末尾容量调整、源镜像检查、管理员权限等待保持在当前进度，不回退。

完成前最高为 99.00%。实盘助手确认写入、读回及引导登记成功后显示 100.00%，结果仍是 `awaiting-device-boot`，需要掌机启动验收；虚拟盘演练在独立 UEFI 登录验证成功后才显示 100.00%。取消、失败、拒绝管理员权限时保留最后百分比和阶段编号。下载使用下载页自己的实际字节进度，不混入上述安装权重。

安装进行中点击关闭窗口会请求停止，等待后端结束当前操作、释放资源并保存日志；清理结束后窗口自动关闭。单独点击“停止安装 / 停止演练”保留窗口用于查看结果和导出日志。清理不会删除已经写入的实盘分区。

## 02.01 密码输入等待修复（2026-10-14）

启用 deck 初始密码时，旧构建可能停在 32% / 02.01，虚拟机最后输出 `OXP_SECRET_INPUT_READY`。主机向 QEMU 模拟串口一次发送整段密码编码可能丢失字符或结束换行，导致虚拟机等待输入或报 `base64: truncated input`。

修复构建在关闭回显的正常行输入模式下，以与启动命令相同的节奏分段发送密码，发送完成只记录 `OXP_SECRET_INPUT_SENT`，不记录密码内容。新增 `--cli secret-input-checks` 使用没有系统镜像和实盘的隔离虚拟机检查完整 UTF-8 密码、私有文件权限和日志保密性。旧的正在运行的进程不会自动获得修复；请使用新包。

## 固定阶段编号

界面示例：**总进度 86.20% · 阶段 04.42**，当前操作显示“正在读回核对：rootfs-A”。百分比保留两位小数用于显示实际进度；固定编号用于准确判断环节，不把小数位强行编码成阶段，避免同一操作的进度失真。诊断时建议同时提供百分比、阶段编号、当前操作与日志。

| 编号 | 操作 |
| --- | --- |
| 01.01 | 解压 / 导入恢复镜像 |
| 01.02 | 官方 SteamOS 3.10 准备（含缓存还原或下载） |
| 01.03 | 创建独立准备盘 |
| 01.04 | 在准备盘部署 SteamOS |
| 01.05 | 导出稀疏 raw 镜像 |
| 01.06 | 按所选安装容量调整 home |
| 01.07 | 检查准备镜像与写入计划 |
| 02.01 / 02.02 | A / B 槽组件配置；界面同时显示最近完成的组件 ID |
| 02.03 / 02.04 | A / B 槽组件独立只读复核 |
| 03.01 | 安装 rEFInd 并保存原启动文件 |
| 04.00 | 等待管理员权限、写盘助手预检和布局准备 |
| 04.90 | 实盘引导登记与收尾检查 |
| 04.99 | 实盘写入与引导登记成功，等待掌机启动验证 |
| 05.01 | 独立虚拟 UEFI 启动验证 |
| 05.99 | 虚拟演练启动验证成功 |

分区编号的两位小数是固定诊断编号：第一位为下表序号，第二位 `1` 表示写入、`2` 表示读回（包括续写前复查）。例如 `04.41` 为 rootfs-A 写入，`04.42` 为 rootfs-A 读回。

| 3 | efi-B | 04.31 | 04.32 |
| 4 | rootfs-A | 04.41 | 04.42 |
| 5 | rootfs-B | 04.51 | 04.52 |
| 6 | var-A | 04.61 | 04.62 |
| 7 | var-B | 04.71 | 04.72 |

每次安装任务目录新增 `progress.jsonl`，每行保存 UTC 时间、`Stage`、`Step`、`Percent` 和 `Message`。续写新增独立 `progress-resume-*.jsonl`，不覆盖前次记录。记录百分比原始数值，界面显示两位小数。详细诊断导出包含任务目录中的进度记录，以及现有 `ui.log`、组件报告、助手日志和磁盘状态。

阶段编号表示当前或最近确认的操作，不是错误分类。组件配置返回最近完成的组件记录后，下一项可能仍在处理中；准确原因要结合组件日志和错误信息。百分比区间也会因跳过选项产生跃迁，不能仅凭一个百分比断定故障原因。
